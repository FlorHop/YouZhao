# 有招前端设计说明（绑定 Open Design 设计体系）

本文是有招改版的**前端设计描述**，与 `docs/permission-design.md` 配套：

- `docs/permission-design.md` 定义**谁能做什么**（角色、范围、接口）。
- 本文定义**界面如何组织、如何交互、如何表达权限**。

**视觉层不在此定义**：配色、字体、字号、间距、圆角、阴影、焦点与动效全部由 Open Design 内置的 `openai` 设计体系（Design System 2.0 包，`id: openai`）决定。本文不复制、也不另行规定任何视觉取值。

## 0. 页面分类

管理能力拆为**两类页面**：

| 页面 | 职责 | 可进入者 |
| --- | --- | --- |
| **用户页** | 账号与人：创建、资料、状态、密码、管理归属 | 平台所有者（全部）、用户管理员（仅其管理的普通用户） |
| **权限页** | 授权：查看范围、管理员任命与可委派范围、业务能力 | 平台所有者（全局）、用户管理员（仅自身范围内） |

凭证（MCP Token）单独成页，属个人自助。

这一划分的关键约束：**用户页不含任何授权逻辑，权限页不含任何账号生命周期操作**。前者改动账号，后者改动权力。

## 1. 设计目标

1. **克制**：视觉语言完全交由设计体系；界面不额外引入装饰、插画或第二套强调色。
2. **以内容为中心**：蓝图预览与管理数据是主角，界面外壳不争夺注意力。
3. **权限可读**：用户能一眼看出“我能改什么、什么是别人给的、什么不能碰”。
4. **范围天生受限**：页面不靠隐藏来保护，而是服务端只返回操作者范围内的数据。
5. **状态诚实**：加载、空、无权限、冲突、失败都有明确呈现，不用假数据填充。
6. **可落地**：每一条描述都能对应到 Vue + PrimeVue 的实现动作。

## 2. 视觉基线：由设计体系决定

配色、字体、字号与行高、间距、圆角、阴影、焦点与动效**全部由 Open Design 的 `openai` 设计体系决定**。本文不列出、不复述这些取值；实现时直接引用该体系定义的语义 token 与组件，禁止在组件内写死色值、字号或自定义圆角。

本文只声明需要用到哪些**语义角色**（取值以设计体系为准）：

| 语义角色 | 用途 |
| --- | --- |
| 页面背景 / 表面 / 次级表面 | 页面底色、面板、分节 |
| 主文本 / 次级文本 / 三级文本 | 正文、说明、占位与元信息 |
| 分隔线 | 区块与表格行分隔 |
| 品牌强调 | 主操作、链接、焦点 |
| 危险 | 删除、归档、重置密码等不可逆操作，以及**破坏性动作的确认框与表单校验错误**提示（裁决：两者共用危险语义） |
| 警示 | 范围缺失、配置不完整等提醒 |
| 成功 | 操作完成反馈 |

排版与组件层面的两条约定（属结构决策，不含取值）：

- 页面标题使用体系中**章节标题层级**，不使用展示级（editorial display）层级；展示级仅用于登录页与空状态等编辑性时刻。
- 直接复用体系提供的按钮、卡片、chip、表单字段等组件，其状态样式以体系为准，不新增体系外的视觉配方。
- **字体按设计体系原样使用**：含 Signifier / Söhne 等商业字体，已确认（个人内部应用，不对外分发），本期**不替换、不引入替代字体文件**；回退链（Source Serif Pro / Georgia / Inter / system-ui）只用于缺字体的环境，不作为设计决策。

## 3. 受控扩展：控制台结构

该体系源自内容型页面（hero、features grid、导语），**没有表格、侧边导航、工具栏、对话框、Toast**。管理页面必须有这些，因此需要**受控扩展**——新增以下结构配方，并遵守三条纪律：所有视觉取值来自设计体系语义 token；**不新增品牌强调色**与自定义圆角；**危险色与警示色是允许的**（破坏性动作与校验错误必须可辨识，见第 9 条裁决）。

| 扩展组件 | 结构说明 |
| --- | --- |
| 侧边导航 | 固定宽度侧栏，右侧一条分隔线；激活项用次级表面区分 |
| 页头 | 页面标题 + 一行说明文字，底部一条分隔线 |
| 指标条 | 3–4 列，上标签下数值，列间分隔线 |
| 数据表 | 表头弱化、单元格常规文本；仅横向分隔线，无斑马纹与外框 |
| 行内操作 | 文本或图标按钮；危险项使用危险语义色 |
| 两栏面板 | 左列用户列表（固定宽度）+ 右列授权面板，中间分隔线 |
| 区段标题 | 小标题 + 说明文字；区段之间以留白分隔，不用卡片包裹 |
| 对话框 | 居中浮层 + 遮罩，底部右对齐按钮 |
| 变更条 | 底部吸附，显示待应用变更数量与增删明细 |
| Toast | 角落浮层，短时提示 |
| 空状态 | 居中说明 + 一个主操作 |

## 4. 信息架构与导航

侧边导航按角色过滤；**不渲染无权访问的入口**。

| 导航项 | 平台所有者 O | 用户管理员 A | 普通用户 U |
| --- | --- | --- | --- |
| 蓝图 | ✓（全部） | ✓（授权范围） | ✓（授权范围） |
| 用户 | ✓（全平台账号） | ✓（仅其管理的普通用户） | — |
| 权限 | ✓（全局授权） | ✓（仅其范围内的授权） | — |
| MCP Token | ✓ | ✓ | ✓ |

**普通用户没有 `用户` 与 `权限` 两个入口。** 这两条路由要求平台所有者或用户管理员身份，导航不渲染、前端守卫拦截、服务端逐接口校验；普通用户直达 URL 一律返回 `/403`。普通用户不得因为“本人”身份而获得 `/users`、`/permissions` 的任何可见性。

**「我的账号」不进主导航。** 它是所有角色（含普通用户）唯一的非导航页面，由顶栏头像或设置入口打开；内容仅限本人资料与密码，**不含**任何用户管理或授权能力，也不提供跳转到 `用户`、`权限` 的路径。

页头右侧固定：姓名、身份标签、退出。身份标签为 `平台所有者` / `用户管理员` / `普通用户`，仅在“用户”“权限”页出现。

## 6. 页面设计描述

### P1 登录 / 首次初始化

- 居中单列，最大宽约 420px；面板承载表单。
- 顶部一句展示级短标题（唯一使用展示衬线的时刻）。
- 表单字段直接使用体系字段组件；主操作按钮通栏。
- 首次部署时同页切换为“初始化平台所有者”，提示“该账号将成为唯一平台所有者，且不可被其他管理员修改”。
- 错误就地以文字提示，不使用弹窗。**不显示**演示账号提示。

### P2 蓝图展示（`/blueprints`）

- 目的：浏览、创建、维护与发布蓝图；**不在此页配置权限**。

**两个层级**

页面由「分组」与「蓝图卡片」两级构成。同一分组的卡片必须收拢在该分组区内，不允许打散平铺。

**1. 分组区**

- 区头：分组名称、卡片数量；默认分组带 `默认` 标签。
- 新建分组：区头级主操作 `新建分组`，仅需分组名称（平台内唯一）。需具备**覆盖目标范围的蓝图管理能力**。
- 排序：无搜索、无分组筛选时，区头提供上移/下移调整顺序；默认分组恒为第一位，不参与排序。
- 归档分组：默认分组不可归档。归档其他分组时，其下蓝图**回落到默认分组**，且该分组的授权同时被移除——确认框必须写明这两项后果，因为它会改变可见性；**产物不物理删除，可恢复**。
- 空分组保留区头并显示“暂无蓝图”占位，以便作为移动目标。

**2. 蓝图卡片**

- 一张卡片 = **一项蓝图任务**，不是一版。多版本都在同一张卡片内。
- 卡片内容：名称、概述摘要、标签、所属分组、当前查看的版本号、更新时间；已归档的带 `已归档` 标签。
- **版本选择在卡片内**：默认选中最新版本；切换只影响当前浏览，**不写回服务端、不改变“最新版本”的判定**。切换后卡片的 `预览` 打开所选版本。
- 仅有一个版本时不显示版本选择器，避免无意义控件。
- 卡片整体点击进入 P3；操作区点击不触发跳转。

**卡片操作按能力装配**

| 操作 | 所需能力 | 说明 |
| --- | --- | --- |
| 预览 | 该蓝图的查看权 | 打开 P3，携带当前选中的版本 |
| 维护 | `blueprint.manage` 覆盖该蓝图 | 编辑名称 / 概述 / 标签、移动分组、归档 |
| 覆盖版本 | `blueprint.manage` 覆盖该蓝图 | 用新产物替换**已存在版本**的内容，版本号不变 |
| 发布新版本 | `blueprint.publish` 覆盖目标分组 | 上传新产物，新增一个版本并设为最新 |
| 归档版本 | `blueprint.manage` 覆盖该蓝图 | 不得归档最后一个可用版本；产物保留，可恢复 |
| 归档蓝图 | `blueprint.manage` 覆盖该蓝图 | 连同全部版本一并归档；**不物理删除产物**，可恢复 |

两者皆无时不渲染操作区，卡片保持纯浏览态。

**页内新建蓝图**

- 入口：页头主操作 `新建蓝图`，与搜索框同行右对齐。
- 表单字段与现有发布参数对齐：蓝图名称（必填）、概述、标签、所属分组（**默认选中默认分组**）、版本号（必填）、发布说明。
- 产物以**上传压缩包**提供：包内需包含入口 `index.html`，可包含其依赖的静态资源。
- 创建即发布：一次提交同时建立蓝图与首个版本；`publishSource` 记为 `web`（现有数据只有 `mcp`，需扩展取值）。
- 名称冲突、版本号冲突就地报错并保留已填内容。

**上传与覆盖的约束**

- 先校验后落盘：包内必须存在入口 `index.html`；拒绝绝对路径与 `..` 路径穿越；超出体积上限时明确报错，不写半成品。
- **覆盖不可逆**：确认框必须写明“将替换 vX.Y.Z 的产物，版本号与发布记录保持不变，原产物无法恢复”。
- 覆盖不新增版本、不改动版本号，只更新产物与哈希；发布才新增版本。
- 写入中途失败必须回滚，卡片上不出现不可用版本。

**页头与工具栏**

- 页头：`蓝图` + 一行说明，显示可见蓝图数量（不显示被拒绝的数量）。
- 工具栏：搜索框、分组筛选（仅当存在多个可见分组时出现）、排序（最近更新 / 名称）、状态筛选（归档仅对有管理能力者出现）。搜索与筛选走服务端，不在前端过滤。

**权限可见性**

- 只渲染服务端返回的可见蓝图；**不渲染**任何“无权查看的其他蓝图”占位或计数，避免泄露资源存在性。

**状态**

- 加载：骨架卡片。
- 空：普通用户显示“你还没有可查看的蓝图，请联系管理员为你分配”；具备创建能力者显示“还没有蓝图”并提供 `新建蓝图` 主操作。
- 失败：就地错误 + `重试`。
- 无权：完全无查看权时不渲染列表，直接进入拒绝态。

**数据一致性与容量**

- 列表接口一次返回卡片渲染所需字段，**禁止逐条再请求详情**（当前实现为按条拉取，需收敛）。
- 权限被撤销或蓝图被归档后，**不得继续渲染本地缓存内容**；进入页面及窗口重新聚焦时以服务端结果为准。
- 服务端单次返回有上限，超出时必须提供分页或“加载更多”，不能静默截断。

**与现状的对照**

| 能力 | 现状 | 本期 |
| --- | --- | --- |
| 分组区、建组、排序、删组 | 已有 | 沿用；补删除后果提示，改由 `blueprint.manage` 判定 |
| 卡片内版本切换（默认最新） | 已有 | 沿用 |
| 编辑蓝图信息、移动分组、归档 | 已有 | 沿用，改由 `blueprint.manage` 判定 |
| 删除蓝图 | 已有 | 沿用；补二次确认与后果说明 |
| 页内新建蓝图 | **缺失**（仅能经 MCP 发布） | 新增 |
| 上传压缩包 | **缺失**（现仅接受单文件 HTML + Markdown 文本） | 新增 |
| 覆盖已有版本 | **缺失**（同版本号直接冲突报错） | 新增 |
| `publishSource` | 固定为 `mcp` | 扩展为 `mcp` / `web` |
| 归档与恢复 | 部分（卡片有归档标记，无恢复入口） | 新增恢复入口；产物一律保留 |

### P3 蓝图预览（`/blueprints/:id/preview`）

- 目的：全屏查看产物，**只读**；不提供任何编辑、发布或权限入口。
- 布局：无应用外壳的全屏视图；顶部悬浮工具条提供 `返回`、蓝图名称、当前版本，以及（存在多个可见版本时）版本切换。默认展示最新已发布版本。
- 隔离与鉴权（硬约束，先于视觉）：
  - 产物在 iframe 中渲染，**必须设置 `sandbox`**，且不授予同源能力；产物不得能读取会话凭证。
  - 会话凭证不得存放在产物可读取的位置（当前存于 `localStorage` 且同源共享，需一并调整）。
  - 产物请求必须携带会话鉴权，**不得匿名可读**；无查看权时不渲染 iframe，直接进入 `/403`。
- 状态：加载中覆盖整个内容区；失败按原因分类呈现——产物缺失 / 版本不存在 / 无权查看 / 加载超时——各给出原因与下一步动作（`返回`、`切换版本`）。
- 多版本：只列出操作者可见的版本；切换版本不改变权限判定。
- 嵌入模式（配合 P7）：在 ticket 会话下只渲染被授权的单一蓝图，隐藏版本切换，工具条收至最小，不出现站内导航。
- 响应式：工具条在窄屏收为图标；内容区始终全屏，不做缩放或裁切。

### P4 用户（`/users`）

- 页头：O 为「用户」+“管理全平台账号与管理归属”；A 为「用户」+“你只能管理平台所有者指派给你的用户，以及由你创建且尚未改派的用户”。
- 指标条：
  - O：用户总数 · 用户管理员数 · 已停用数
  - A：我管理的用户数 · 其中已停用数
- 工具栏：搜索框、状态筛选、（O 额外）归属管理员筛选、右对齐主按钮 `新建用户`。
- 表格列：姓名 · 用户名 · 管理归属（**可能多位**，逗号分隔） · 状态 · 创建时间 · 操作。
- **不出现**“可查看范围”列：授权在权限页配置。行内提供 `查看权限` 链接跳到 P5 并带入该用户。
- **所有者行**：身份标签 `平台所有者`，操作列仅显示 `受保护` 说明文字，无编辑/停用/删除/重置。这是权限模型的可见承诺。
- **用户管理员行**（O 视角）：操作含 `编辑`、`改派管理员`、`查看权限`、`停用/启用`、`重置密码`、`删除`。
- **普通用户行**：同一组操作（含 `删除`，仅 O 可见）；A 视角下无 `改派管理员`，且**不提供 `删除`——用户管理员对名下用户只能停用**。
- A 视角**不出现**身份列。
- 危险操作用二次确认说明后果与可恢复性，不使用通栏红色按钮。
- 空状态：A 未被指派任何用户时显示“还没有归你管理的用户”，并说明需由平台所有者指派。

**新建用户对话框**：

- 只含两段：`账号信息`（用户名必填、姓名、邮箱、手机号、初始密码，带显示/隐藏切换）与 `管理归属`（O 可**多选**管理员，留空表示暂不指派；A 只读显示“归属：你”）。
- **不出现**身份选择、查看范围、业务能力、Token 相关选项。
- 底部按钮：`取消` / `创建用户`。创建成功后 Toast 提示，并在 Toast 与页面同时提供次操作 `去分配查看范围` → 跳转 P5 并选中该用户。这样既保持“创建与授权”的连贯感，又不把授权逻辑塞进用户页。

### P5 权限（`/permissions`）

整页由**区段**组成，不用标签页；区段按身份裁剪，页头说明随身份变化。

**区段一：查看范围分配**（O 与 A 都可见）

- 布局：左列用户列表（固定宽度）；O 看到全部普通用户与用户管理员，A 只看到 `managedByUserIds` 含自己的普通用户（**一个用户可同时归属多位管理员**，此时每位都能管理，但都不能删除或改派）。右列为该用户的授权面板。
- 右列分区：
  - `我可以调整的`：可选中的分组 / 单蓝图列表，选项**仅为操作者获准委派的范围**。
  - `其他人授予的`：**只读**，逐项标注授予者与时间，不可取消。**A 视角同样显示**（已裁决）：这是他理解“某用户为何能看到某蓝图”的唯一渠道。
- 保存为**增量语义**：底部吸附变更条显示待应用变更数量与 `+ 新增 / − 撤销` 明细；无变更时主按钮禁用。
- 冲突：权限已被他人变更时就地提示“权限已发生变化，请刷新后重试”并提供 `刷新`，**不覆盖**。
- A 进入时页头说明：“你只能为你管理的用户分配你获准委派的范围；其他来源的授权不可修改。”
- 切换用户前若有未保存变更，先确认。

**区段二：管理员与可委派范围**（仅 O）

- 列表：用户管理员 · 当前管理用户数 · 可委派范围摘要（即**其本人的查看范围**）。
- **可委派范围不单独设置**：它等于该管理员自己在区段一被授予的查看范围，随之变更。因此行内操作是 `查看其范围`（跳转区段一并选中该管理员），而不是“调整范围”。
- 底部说明：“该范围决定此管理员能为其管理的用户开放哪些蓝图，**不包含**蓝图管理与发布权；它不单独维护，而等于该管理员自己被授予的查看范围。”
- `添加用户管理员`：选择普通用户 → 确认；随后在区段一为该管理员分配查看范围。

**区段三：业务能力**（仅 O）

- 列表：用户 · 能力（蓝图管理 / 蓝图发布）· 资源范围 · 授予时间。
- `添加授权`：选择用户 → 选择能力 → 选择范围。必须显式选择范围，**不存在“全部分组”默认值**。
- 说明：“授予此处能力后，该用户才能在指定范围内维护或发布蓝图；这与能否管理账号无关。”

**区段四：所有者移交**——**本期不提供**（已裁决：暂不设计，短期内不会发生）。因此权限页在所有者视角只有三个区段；不渲染入口，也不保留灰色占位。

### P6 MCP Token（`/tokens`）

- 页头说明：“Token 代表你本人，只能访问你当前有权查看的蓝图；权限被撤销后立即失效。”
- 工具栏：`创建 Token`（主操作）；O 额外提供“绑定用户”筛选。
- 创建对话框：名称（必填）、能力（单选 `只读` / `发布`；`发布` 仅在具备发布能力时可选并显示生效范围）、有效期（默认“永不过期”）；**O 额外有 `绑定用户` 选择器**——可为任意用户创建（须显式指定）；A 与普通用户无此项，只能为自己创建。
- **Token 原文只在创建成功后展示一次**：面板 + 等宽字体展示，附 `复制`，醒目标注“关闭后无法再次查看”。
- 列表列：名称 · 标识（等宽）· 能力 · 状态 · 最近使用 · （O）绑定用户 · 操作（停用/启用、删除）。
- 普通用户与用户管理员**只看到自己的 Token**（用户管理员看不到名下用户的 Token）；O 可查看全部、可为任意用户创建并停用，但同样**无法查看原文**。Token 的能力是**下限附加**：实际可用能力 = 绑定用户当下权限 ∩ Token 自身 scope，绑定用户被撤权后立即收窄。

### P8 我的账号（`/account`）

- **入口**：顶栏头像菜单与侧栏设置按钮，点击打开；**不出现在主导航列表**，日常不被展示。
- 全部角色可访问；页面只呈现本人信息，**不含**用户列表、授权配置或任何他人数据。
- 区段：
  - `账号资料`：用户名（只读）、姓名、邮箱、手机号。
  - `修改密码`：原密码 + 新密码；成功后保留当前会话并提示。
  - `我的身份与范围`（**只读**）：身份标签；用户管理员显示其可委派范围；具备业务能力者显示能力与资源范围；普通用户显示其获授的查看范围并按来源标注。此区段仅展示，不可编辑——调整必须由有权限者在权限页进行。
  - `退出登录`。
- 若操作者是普通用户，本页**不出现任何管理入口**，也不能由本页进入 `用户` 或 `权限`。

## 7. 权限可视化规范

| 界面语义 | 表达方式 |
| --- | --- |
| 允许且可编辑 | 常规交互控件，主文本 |
| 只读（他人授予） | 纯文本 + 授予者与时间（次级文本）；无勾选框 |
| 受保护（所有者） | 不出现危险操作，仅一行 `受保护` 说明 |
| 越权不可用 | 不渲染入口；URL 直达则显示 `/403` 页 |
| 超范围（可委派范围外） | 不列出该项，而非置灰；接口拒绝时提示“超出你的可委派范围” |
| 危险动作 | 危险语义色 + 二次确认 |
| 变更待提交 | 底部变更条显示待应用变更数量 |
| 权限已变更 | 就地提示 + `刷新`，不静默覆盖 |

## 8. 关键交互流程

1. **创建账号**（O/A）：`用户` → `新建用户` → 填账号信息 → 选归属 → 创建 → Toast 提供 `去分配查看范围` → 跳 `权限` 并选中该用户。
2. **分配查看范围**（O/A）：`权限` → 左列选用户 → 勾选/取消 → 变更条显示差异 → `保存`；冲突则 `刷新` 后重试。
3. **改派管理归属**（O）：`用户` → 行内 `改派管理员` → 选择归属管理员（**可多位**，整体替换）→ 确认框说明“原管理员将立即失去管理权，该用户已有的查看权不会自动清除”。
4. **任命管理员**（O）：`权限` → 区段二 → `添加用户管理员` → 选用户 → 设置可委派范围 → 确认。
5. **授予业务能力**（O）：`权限` → 区段三 → `添加授权` → 选用户 → 选能力 → 选范围 → 确认。
6. **撤销生效**：停用用户或撤销查看权后，其 Token 与会话立即失效；被撤销者下次请求返回 401/403，前端跳登录或 `/403`。
7. **所有者移交**：**本期不提供**（已裁决暂不设计）；权限页不出现该区段，也不保留任何入口。

## 9. 文案规范

| 场景 | 文案要求 |
| --- | --- |
| 权限边界 | 说明“能做什么”和“不能做什么”，不只说“无权限” |
| 只读来源 | 明确“由 X 于 Y 时间授予” |
| 危险确认 | 说明后果与是否可恢复 |
| Token | 强调“代表本人”“一次可见”“撤权即失效” |
| 错误 | 就地说明原因与下一步动作，不用通用“操作失败” |

## 10. 响应式与可访问性

- 断点：≥1200px 侧栏常驻；768–1199px 侧栏收为图标；<768px 侧栏转抽屉。
- P5 两栏在 <1200px 改为「先选用户再进入授权」的单栏流程。
- 对比度：正文与背景对比度达标；次级文本色仅用于次要信息。
- 键盘：所有操作可键盘到达，焦点样式由设计体系提供且必须可见；对话框焦点锁定、Esc 关闭。
- 表格语义化，操作按钮带可读名称；动效尊重 `prefers-reduced-motion`。

## 11. 技术落地（Vue + PrimeVue）

- 用 `definePreset` 把设计体系 token 映射到 PrimeVue 主题变量，避免逐组件写死样式；映射以设计体系为准，不在前端复制取值。
- 映射不足时以设计体系 token 覆盖，**不引入独立色板**。
- 本期仅浅色：该体系无深色 token；如需深色必须新建设计体系包。
- 表格信息密度如需比正文更紧凑，在体系提供的档位内选择，不自定义字号。
- P4/P5 的数据范围一律由服务端裁剪，前端**不做权限过滤作为安全边界**。
- `用户`、`权限` 的访问控制是**身份级**而非数据级：普通用户整体不可进入，不由“能看到几条数据”决定。路由守卫与服务端接口两层都校验。
- 本人自助走独立命名空间（`/api/me/*`）：`/api/users/*`、`/api/admins/*`、`/api/owner/*` 对普通用户整体拒绝，避免“本人”分支成为进入用户管理接口的侧门。
- 蓝图预览（P3）为全屏 iframe：保持无外壳，但**必须**补齐 `sandbox` 与来源隔离（见权限审计结论）。
- 压缩包上传要求产物按**多文件**存储与路由，而当前产物路由只服务单文件 `index.html`（多文件产物支持目前只在未合并分支上）。需先落地多文件产物服务，或本期明确限制为单文件包。
- 会话 Token 存储位置在改版中一并收敛，不继续放在可被产物 iframe 直接读取的位置。
- **图表本期需要**（裁决）：使用 ECharts（`frontend-rules.md` §1 已列）。图表容器、网格线、tooltip 与系列配色一律取自设计体系语义 token，**不引入图表专用色板**。
- **不保留并行旧接口**（裁决）：前端只对接新版 `/api/*`，不做双版本兼容层，也不保留旧页面。

## 12. 与 Open Design 的对接

- 设计体系：使用内置 `openai`（`design-systems/openai`）；生成前将项目设计体系设为该包，并在提示中声明“仅使用该包 token，禁止裸 hex”。
- Open Design 提供本地 CLI（`od`），可脚本化触发：`od automation create --prompt ... --target new-project` 配合 `od automation run <id>`；`od artifacts create` 可写入产物。是否走 CLI 由你决定，界面投喂同样可行。
- 投喂方式：把本文作为附件放入项目并在会话中引用；附件会被截断，建议**先给第 2–4 节**（视觉基线、扩展结构、导航），确认后再给第 5、6 节（页面清单与逐页描述）。
- 生成批次建议：第一批 P2 + P3（蓝图展示与预览，含隔离约束）；第二批 P4（用户）；第三批 P5（权限，含三个区段）；第四批 P6 + P8（Token 与我的账号）。
- 验收要点：未改写设计体系 token、无裸 hex、未新增品牌强调色（危险与警示语义除外）、所有者行无危险操作、只读授权不可勾选、变更条存在、P5 区段按身份正确裁剪、P2 卡片按能力装配操作区且同组卡片不被打散、P2 的覆盖确认写明不可逆、P3 的 iframe 带 `sandbox` 且产物请求带鉴权、破坏性动作与校验错误使用危险语义且可辨识、图表已接入且未自带色板。
